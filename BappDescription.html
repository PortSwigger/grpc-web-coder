Decodes and re-encodes gRPC-Web request and response bodies in the message editor, without needing the target's .proto schema. gRPC-Web bodies are protobuf wrapped in length-prefixed frames, and application/grpc-web-text bodies are base64 on top of that, so they arrive as an opaque blob that ordinary testing techniques do not reach. This extension unwraps the framing, infers a type for every protobuf field, and shows the result as editable JSON. Edits are re-encoded on the way out, so a payload can be tampered with in Proxy, Repeater and Intruder like any other request body.

Features

  • Adds a decoded gRPC-Web tab to requests and responses, with the payload as JSON and an editable type definition alongside it.
  • Guesses a type for each field from the wire format, and lists the other readings the same bytes would allow, so an ambiguous field can be reinterpreted without trial and error.
  • Handles every frame in a body, including the multiple data frames of a server-streaming response and the trailer frame that closes it.
  • Inflates and re-deflates gzip-compressed frames.
  • Supports proto3 packed repeated fields, which are indistinguishable from a bytes field on the wire.
  • Extracts service routes and message field definitions from generated gRPC-Web JavaScript, revealing methods that no part of the application's UI calls.
  • Exports those findings as JSON, CSV, a reconstructed .proto for protoc or grpcurl, or as type definitions that make payloads decode with their real field names.
  • Supports application/grpc-web-text, application/grpc-web-text+proto, application/grpc-web+proto and application/grpc-web.

Usage

  1. Send a gRPC-Web request through Burp and open the Decoded gRPC-Web tab in Repeater. Field names are not carried on the wire, so fields appear by number until you name them in the type definition.
  2. Edit the payload as JSON, then switch back to the raw view. The body and Content-Length are re-encoded for you.
  3. Right-click the response containing the site's gRPC-Web JavaScript bundle and choose Analyze gRPC-Web Endpoints to recover the real field names and numbers.
  4. Export those results as type definitions and paste them into the Type Definition tab, which makes every subsequent payload readable.

For a walkthrough of testing gRPC-Web Coder, see https://github.com/nxenon/grpc-pentest-suite.
